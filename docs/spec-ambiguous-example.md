# 曖昧な仕様と、判断できる仕様

AIにテストを任せるとき、仕様の書き方で結果が変わります。曖昧な仕様では、AIが合否の基準を自分で決めてしまい、テストのたびに判断がぶれます。

## 比べてみる

| 曖昧な仕様 | 何が決まっていないか | 判断できる仕様（[spec.md](spec.md)） |
|---|---|---|
| 実績を業種で絞り込めること | 「絞り込めた」をどう確かめるか。ボタンの見た目が変わればよいのか | SPEC-02：業種のボタンを選ぶと、その業種に属する実績だけを表示する。他の業種の実績は表示しない |
| 絞り込みを解除できること | 解除後に何件、何が表示されるべきか | SPEC-03：「すべて」を選ぶと、公開済みの実績がすべて表示される（件数は [test-data.md](test-data.md) で9件） |
| 該当がないときも問題なく表示されること | 「問題なく」とは何か。空白でよいのか、メッセージが要るのか | SPEC-07：「該当する実績はありません。」と表示する |
| 実績の詳細情報を表示すること | 未入力の項目をどう扱うか | SPEC-04：制作年が未入力なら、表に「制作年」の行（見出しと値）を表示しない |
| お問い合わせフォームが使えること | どの項目が必須か。入力に誤りがあるときどうなるか | SPEC-05／SPEC-12／SPEC-13：必須項目、形式、エラー表示、入力の保持まで定義 |
| 送信できること | 何をもって「送信できた」とするか | SPEC-06：送信完了ページへの移動と、確認用メールボックスへの到着の両方 |

## 判断できる仕様の条件

- **操作と期待結果がセットになっている。** 「〜を選ぶと、〜だけを表示する」のように、何をしたら何が起きるかが書かれている。
- **合否が一つに決まる。** 件数、表示される文言、移動先のURLなど、確かめられる形で書かれている。
- **正常な場合以外も書かれている。** 0件、未入力、入力の誤り、未公開のデータなど。
- **テストデータと結びついている。** 「飲食は3件」のように、期待する結果が具体的な数や名前で分かる。

## AIに渡すときの注意

仕様に書かれていないことをAIが見つけた場合は、AIに合否を決めさせず、「仕様の確認事項」として記録させます。
