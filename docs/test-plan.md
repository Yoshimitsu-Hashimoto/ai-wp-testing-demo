# テスト計画（解答例）

[仕様書](spec.md) と [テストデータ](test-data.md) から作成したテスト計画の例です。講座では同じ資料からAIにテスト計画を作らせ、この例と比べます。

## 1. 目的と範囲

- 目的：仕様書の受け入れ条件（SPEC-01〜SPEC-13）を満たしているかを確かめる。
- 範囲：制作実績一覧、制作実績の詳細、トップページの制作実績欄、お問い合わせフォーム。
- 範囲外：仕様書の「対象外」に挙げたもの（会社案内・プライバシーポリシー・お知らせ・ヘッダーとフッター、管理画面、デザインの細部、性能）。

## 2. 環境と前提

| 項目 | 内容 |
|---|---|
| サイト | http://localhost:8090/ |
| 確認用メールボックス | http://localhost:8091/ （Mailpit） |
| ブラウザ | Chromium（Playwright） |
| 状態 | 管理画面にログインしていない |
| テストデータ | 実行前に `./scripts/seed.sh` で初期状態に戻す（確認用メールボックスも空になる） |
| 自動テスト | `tests/e2e/`。`npm test` で全件を実行する |

## 3. テストの観点

| 観点 | 内容 |
|---|---|
| 正常系 | 仕様どおりの操作で、期待どおりの表示・送信になるか |
| 異常系 | 未入力・形式の誤り・同意なしで、送信が拒否されるか。未公開のデータが出ないか |
| 境界・特殊な条件 | 0件の業種、存在しない業種、空の指定、大文字のスラッグ、任意項目の未入力、空白だけの入力 |
| 組み合わせ | 1項目だけ誤りがあり、他は正しい入力のときに正しく拒否されるか（他の項目の誤りに隠れないか） |

## 4. テストケース

分類：正＝正常系、異＝異常系、境＝境界・特殊な条件

テストケースに必要な項目は次のように分けて持つ。

| 項目 | 置き場所 |
|---|---|
| テストID・仕様ID・操作手順・期待結果 | 下の表 |
| 前提条件 | 2章の共通の前提。テストごとの前提は「手順」に含める |
| 実行結果・証拠 | 実行ごとのテスト実行記録（実行日・ブランチ・結果・スクリーンショットなど） |

### 制作実績一覧（`tests/e2e/works-list.spec.ts`）

### お問い合わせ（`tests/e2e/contact.spec.ts`）

各テストの前に確認用メールボックスを空にする。「送信できない」は、お問い合わせページに留まり、エラーが表示され、メールが届かないことで確かめる。

| TC | 仕様ID | 分類 | 手順 | 期待結果 |
|---|---|---|---|---|
| TC-15 | SPEC-06 | 正 | すべて正しく入力し、同意にチェックして送信 | `/thanks/` に移り「お問い合わせを受け付けました。」。宛先 admin@example.test、件名「【株式会社ひなた】お問い合わせ（山田 太郎 様）」、Reply-To が入力したアドレス、本文に3項目を含むメールが1通 |
| TC-16-1〜3 | SPEC-05, 13 | 異 | お名前・メールアドレス・お問い合わせ内容を1つずつ空にし、他は正しく入力して送信 | 送信できない。空にした項目のエラーメッセージだけが出る |
| TC-17 | SPEC-05, 13 | 異 | 同意だけチェックせず、他は正しく入力して送信 | 送信できない。「プライバシーポリシーへの同意が必要です。」だけが出る |
| TC-18 | SPEC-05, 13 | 異 | 何も入力せずに送信 | 送信できない。4つのエラーメッセージがすべて出る（表示順は問わない） |
| TC-19-1〜4 | SPEC-12 | 異 | メールアドレスを `yamada`・`@example.test`・`yamada@`・`yamada@example` にして送信 | 送信できない。「メールアドレスの形式が正しくありません。」 |
| TC-20 | SPEC-05 | 境 | お名前を全角・半角スペースだけ、内容を空白と改行だけにして送信 | 送信できない。お名前とお問い合わせ内容のエラーが出る |
| TC-21 | SPEC-13 | 異 | メールアドレスだけ `yamada@example` にし、他は正しく入力して送信 | 送信できない。入力したお名前・メールアドレス・内容（改行を含む）と同意のチェックが残っている |
| TC-22 | SPEC-06 | 境 | お名前を「　山田 太郎 」、メールアドレスを「 yamada@example.test　」（前後に全角・半角スペース）にして送信 | 送信完了ページに移動する。件名は「（山田 太郎 様）」、Reply-To は `yamada@example.test` で、前後の空白が取り除かれている |

## 5. 仕様の確認事項

仕様書に書かれていないため、合否を付けずに記録するもの。

| No | 内容 |
|---|---|
| Q-01 | 送信完了ページ（`/thanks/`）を、送信せずに直接開いた場合の扱い（現在は完了メッセージが表示される） |
| Q-02 | 各入力項目の文字数の上限 |
| Q-03 | 同じ内容を続けて送信した場合（二重送信）の扱い |

## 6. 結果の記録

実行結果は、テストケースごとに「合格／不合格」と証拠（スクリーンショット、トレース、実行ログ）をテスト実行記録に残す。不合格はバグ管理表（[bug-list.md](bug-list.md)）に記録する。
