# バグ管理表

テストで検出した不具合を記録します。1件につき1行とし、GitHub Issueを作成したらIssue URLを記入します。

| バグID | 仕様ID | 概要 | 再現手順 | 期待結果 | 実際の結果 | 重要度 | 証拠 | Issue URL | 対応状況 |
|---|---|---|---|---|---|---|---|---|---|

## 記入ルール

- バグIDは `BUG-01` から連番で付ける。
- 仕様IDは `docs/spec.md` の受け入れ条件のIDを書く。
- 期待結果は仕様書の記述に基づいて書き、推測で決めない。
- 証拠にはスクリーンショットやトレースのファイルパス、テストの実行記録を書く。
- 重要度は「高・中・低」のいずれか。判断基準は下の表のとおり。
- 対応状況は「未対応・修正中・再テスト済み」のいずれか。

## 重要度の判断基準

| 重要度 | 基準 |
|---|---|
| 高 | 主要機能が仕様どおりに動かない、または個人情報の取り扱いに関わる |
| 中 | 一部の条件で仕様どおりに動かない |
| 低 | 表示上の問題など影響が小さい |
