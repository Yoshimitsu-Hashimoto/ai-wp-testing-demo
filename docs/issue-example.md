# GitHub Issueの記入例

[バグ管理表の記入例](bug-list-example.md) の BUG-01 を、Issueテンプレート「バグ報告」（`.github/ISSUE_TEMPLATE/bug_report.yml`）で起票した場合の例です。

---

**タイトル**：[BUG-01] 業種で絞り込んでも、制作実績一覧が全件のまま表示される

**ラベル**：bug

### バグID

BUG-01

### 仕様ID

SPEC-02（関連：SPEC-07）

### 概要

制作実績一覧で業種のボタンを選ぶと、ボタンは選択状態になるが、一覧は絞り込まれず公開済みの全9件が表示される。

### 再現手順

前提条件：
- `./scripts/seed.sh` でテストデータを投入した状態
- 管理画面にログインしていない

手順：
1. http://localhost:8090/works/ を開く
2. 業種のボタン「飲食」を選ぶ（URLは `/works/?industry=food` になる）
3. 表示された実績と件数を確認する

### 期待結果

- 飲食の3件（和食処 やまの葉 様、カフェ こもれび 様、ベーカリー麦の音 様）だけが表示される（SPEC-02）
- 件数の表示は「3件の実績」（SPEC-08、`docs/test-data.md` の期待件数）
- 「医療」を選んだ場合は「該当する実績はありません。」と表示される（SPEC-07）

### 実際の結果

- 「飲食」ボタンは選択状態になるが、全業種の9件が表示され、件数は「9件の実績」
- 「製造」「サービス」「医療」を選んだ場合や、URLで `?industry=FOOD` や存在しない業種を指定した場合も、同じく9件が表示される

### 重要度

高：主要機能が仕様どおりに動かない

### 証拠

- スクリーンショット：`docs/evidence/TC-03-1-buggy.jpg`（「飲食」が選択状態で9件表示）
- 自動テスト：`npm test` で TC-03-1〜3、TC-04〜TC-07 が不合格
- トレース：`npx playwright show-trace test-results/<TC-03-1のフォルダ>/trace.zip`

### 修正後の確認条件

- 失敗したテスト：TC-03-1、TC-03-2、TC-03-3、TC-04、TC-05、TC-06、TC-07 が合格すること
- 関連テスト：`npm test` で全テストを実行し、他のテストが不合格にならないこと（特に TC-01、TC-02、TC-08 の「すべて」の表示）
- テストの期待結果は変更しない（仕様に合わせて実装を直す）

---

## 書き方のポイント

- **仕様IDを書く。** 何を満たしていないかが明確になり、修正後にどのテストで確かめるかも決まる。
- **期待結果は仕様書とテストデータから書く。** 「絞り込まれるべき」ではなく、件数とタイトルまで書く。
- **同じ原因の症状はまとめる。** 「製造でも」「医療でも」を別のIssueにせず、1件の中に書く。
- **修正後の確認条件を書く。** 修正したAIや人が、どのテストを実行すれば完了と言えるかが分かる。
